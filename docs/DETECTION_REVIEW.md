# Saved detector candidates to phone and Quest review

`adapters.detections_to_review` connects the existing `adapters.detect_fungi` output to the shared review inbox. It crops actual pixel boxes, uploads each JPEG through the existing review bridge, and requests local classifier guesses. Phone and Quest clients receive the same finds through their normal polling feed. This is saved-image replay; a physical camera/flight driver is still required for live capture.

```powershell
runtime-vision\Scripts\python.exe -m adapters.detections_to_review --detections experiments\my-detection.json --image data\original-frame.jpg --output-dir experiments\candidate-review-001 --session-id survey-2026-10-26 --evaluation-only
```

Use `--evaluation-only` for any existing test/validation/research image. A report that already declares `evaluationOnly: true` or `synthetic: true` automatically forces evaluation-only upload; omitting the CLI flag cannot downgrade it. Both source flags must be booleans when supplied, and their provenance survives review and scout export. For a newly captured field sequence, retain one `--session-id` across its related frames. `--station https://YOUR-STATION` and `MYCOSCOUT_TOKEN` select an authenticated remote station; HTTP is accepted only on loopback. `--prepare-only` writes crops without uploading. `--no-classify` uploads them for manual review without calling the model.

The adapter accepts `mycoscout.unlocated-candidates.v1` and `mycoscout.color-proposals.v1`, including SHA256, image dimensions and the EXIF-oriented pixel convention emitted by the detector/color proposer. Color reports must declare `colorOnly: true`; their `contrastScore` is used to order cues, not to assert fungal presence. It ignores any embedded input path and opens only the explicitly supplied `--image`. Source bytes and oriented dimensions must match the report. JPEG/PNG sources are limited to 50 MB/40 megapixels. Unsupported, nonfinite, empty or out-of-frame boxes are recorded as rejections rather than assigned invented coordinates.

The default keeps the ten highest-scoring valid candidates. `--max-candidates` allows 1–50. `--padding` adds a fraction of each box dimension on each side (default 0.15, maximum 0.5), clamped to the source image. JPEGs preserve aspect ratio and fit within `--max-edge` (default/maximum 2048). EXIF is not copied. The output directory must be new: crops and JSON reports are never replaced. A classifier failure leaves the uploaded image available for human review; upload and classification errors appear in `review-results.json` and produce a nonzero CLI exit status.

Each crop retains original/padded pixel boxes, detector score, original frame SHA256, content-derived frame ID, source/crop dimensions and detector model revision. All siblings share a stable parent-frame group in addition to the survey session. Original capture time remains null; depth and pose remain unknown. No review event or confirmed label is submitted. Detector scores are not species probabilities.

Color cues carry a bounded `colorEvidence` object: method `lab-local-contrast-v1`, `maxDeltaE`, `meanDeltaE` (finite 0–400), `contrastScore` (0–1), and whether an enhanced view was used. Other supplied fields are discarded. DeltaE measures local color difference; it is not a mushroom or species probability. Color-only proposals always become habitat follow-ups and do not request the mushroom classifier, even if a caller supplies `cueType: detector`. A normal detector box can retain color evidence as additional context while its species guesses still require human review.

Every saved cue has `metadata.investigation`: `routingCategory`, `originalKind`, `rangeEvidence`, `humanConfirmationRequired`, and `photoStatus`. Color/scene cues use `habitat_followup`; ordinary saved detector boxes use `unlocated_followup`. Original range remains `unknown`. A caller's measured-range claim, synthetic pixel-scale distance, pose, capture time, species, or requested routing category cannot change this archive contract. The flight queue handles real measured-range routing separately: sufficiently supported near cues can request immediate investigation, while distant or uncertain cues remain habitat follow-ups. An archive photograph alone cannot start a visit.

`frameCaptureGeometry` records the original image dimensions, original target box and its width/height fractions in the original frame. It asks for a fresh close photograph with a desired 70% native image-width fill, subject to safe standoff; it explicitly marks `physicalCloseCapture: false` and `digitalCropCountsAsPhysicalVisit: false`. Enlarging a crop cannot satisfy the request for a real visit or add detail that the original camera did not capture. All saved candidates remain unconfirmed until a person reviews the closer evidence.

The shared validation also feeds `vision.export_scout_leads`. Color-only proposals enter the archival scout log as `kind: habitat`, `cueType: color_salience`, with their contrast evidence and investigation request. Both image and color reports preserve null capture time and omit metric targets. The exporter never converts the illustrative 10/20/50/100 m pixel-scale test labels into physical distance measurements.

Training exports preserve the original frame hash at `provenance.sourceMetadata.parentImageSha256`. The reviewed-data importer uses it to link crop siblings and inherit the frozen partition of a known corpus parent. A crop from an evaluation frame cannot silently become training data. Unknown-parent crops remain grouped together; conflicting source partitions are quarantined. Human review and photo-rights opt-in are still required before any training export. Keep the parent image's attribution/permissions in the source collection and review record; this detector JSON format does not itself supply a photo license.

Use optional `--source-manifest data/your-frozen-corpus/manifest.json` to preserve original credit. The adapter reads only a local `images[]` manifest and requires its row's SHA256 to exactly match the original frame. It copies only `photoLicense.attribution`, `photoLicense.url`, and `sourceUrl`; flat `attribution`/`licenseUrl` aliases serve the review UI. Credit URLs must use HTTPS. Coordinates, taxon labels and other source fields are omitted. Conflicting matching rows or a missing match fail before crop creation. Without this option, no license is inferred. Training opt-in remains false in either case.

For normal review, export and retraining, see [camera-to-headset review](HUMAN_REVIEW.md) and [review database](REVIEW_DATABASE.md).

## Color-sensitive analysis of a new saved frame

`adapters.scout_frame` is the reusable frame entry point. An explicit `--color-sensitive` flag runs the local GroundingDINO detector on the original image and on a separate enhanced color view, then suppresses overlapping boxes at IoU 0.5 while keeping the highest detection score. It also generates separate local-color habitat proposals. Without the flag, it runs only the original detector pass. This experiment does not establish that color enhancement improves mushroom detection.

```powershell
runtime-vision\Scripts\python.exe -m adapters.scout_frame --image data\original-frame.jpg --output-dir experiments\frame-001 --color-sensitive --max-candidates 10 --max-color-cues 12
```

Add `--station http://127.0.0.1:8787 --session-id my-survey` to send the original-pixel crops to the review inbox. Add `--evaluation-only` for corpus, synthetic, test or replay evaluation material, and `--source-manifest` to retain licensed attribution. Without `--station`, all output stays in local files. All color-only uploads bypass species classification. A failed detector classification leaves its original photo pending for a human, appears in `classificationErrorCount`, and makes this frame command return a nonzero result.

The output directory must be new. It contains `detector-candidates.json`, `color-proposals.json`, `archive-leads.json`, and `summary.json`, plus review crop reports when uploads are requested. Each report refers to the original EXIF-oriented frame dimensions and byte hash. Enhanced image pixels are not substituted into review photographs. Duplicate suppression does not combine detector scores into a probability. The raw and enhanced candidate counts and inference durations remain visible in the report.

Only an existing local model directory is accepted (`--model`, default `models/grounding-dino-tiny`); model downloads and remote code are disabled. A standalone `model.safetensors` is required and its checksum is recorded. `--threads` is limited to 1–8, input to 8 megapixels/50 MB, and each detector/color output budget to 1–50. At most two sequential detector passes run per image. A long-lived camera adapter can import `LocalDetector` once and call `inspect_frame` sequentially, with its own backpressure; no continuous camera driver is represented by this saved-frame command. A synchronized live geometry adapter is still required before an aircraft can approach a cue.

Validation for this change: 21 offline bridge/scout checks passed. The actual local color proposer produced two cues from a licensed archive photo, which were stored in a separate test station with credit, original frame hash, unknown range, no predictions, no human reviews, and no training export records. A separate two-pass real-model smoke took 19.56 seconds for analysis on this CPU (excluding model load/upload), produced three raw and three enhanced boxes, and deduplicated them to one unverified detector candidate plus two color cues; all three uploaded to the same isolated test station. Its initial classifier request failed because the test server could not start a child process; after restarting that server with child-process access, the existing detector find received a prediction without another upload. The original failure and successful retry are retained separately. Color-only cues were never classified. These are plumbing checks, not measured detection accuracy.
